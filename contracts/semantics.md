# Семантика Wise Way v1

[OpenAPI](openapi/wiseway-v1.yaml) задаёт методы, поля, ограничения и ошибки. Здесь — общие правила взаимодействия. Контракт подготовлен backend; совместная приёмка frontend/QA ещё не проведена.

## Транспорт и доступ

- JSON UTF-8, `/api/v1`; неизвестные поля отклоняются. Обязательный nullable-ключ нельзя опускать. Время — UTC с `Z`, размеры — байты.
- Без сессии доступны health/login. WORKER имеет общий доступ к опубликованным корням, компаниям, справочникам и BUSINESS-журналу. ADMIN дополнительно видит SYSTEM и управляет пользователями/настройками вне этого API.
- Cookie `wiseway_session`: HttpOnly, SameSite=Lax, Path=/, без Domain; Secure при HTTPS. HTTP — только loopback-демо. Logout, истечение и блокировка отзывают доступ; автора определяет сессия.
- Login проверяет Origin. Записи требуют Origin и `X-CSRF-Token` из login/session. Читающие POST search, facet, queue/query, audit/query, resolver не требуют CSRF; simulation/selection/preview требуют. Токен хранится в памяти вкладки. CORS допускает конкретный UI origin с credentials.
- Ответы: `X-Request-ID`, `Cache-Control: no-store`; ID ошибки совпадает с заголовком. Логи не содержат паролей, токенов, поискового текста, тел запросов и физических путей.
- Пути логические: root ID + относительный путь. `display_path` предназначен для отображения/копирования; resolver принимает существующие разрешённые цели с префиксом `DEMO:/SandboxRoot`. Повторное URL-декодирование запрещено; `%2e` — буквальное имя.

## Поиск

- Нужен один опубликованный корень. Пробелы вне кавычек нормализуются до выбора режима: пустой текст без маркеров даёт IDLE, `items=[]`, `total=null` и первый фасет. Иначе RESULTS, включая точный ноль.
- Маркеры: непрерывная цепочка, одно raw-значение на уровень, AND с текстом. Первый нераспознанный уровень останавливает разбор; файл доступен по имени/пути и распознанным родителям. UNRECOGNIZED завершает каскад. Лишний хвост: `StructureIssue.level_id=null`, `level_name=Дополнительный уровень`.
- Все слова обязательны, совпадение — начало токена без учёта регистра. Разделители: пробел, дефис, подчёркивание, точка, слеши, переход буква↔цифра. Кавычки требуют соседних полных токенов: `"atlas main"` подходит к `Atlas-Main`, но не `Atlas-Maintenance`. Незакрытая кавычка — INVALID_QUERY. Нет OR/NOT, regex, escape, fuzzy и поиска по содержимому.
- `facet_prefix` фильтрует только варианты. Counts точны для AND-пересечения; нули скрыты, варианты не усекаются. Порядок: natural value → raw value → ID; UNRECOGNIZED последний. `/search/facet` получает только родителей редактируемого уровня.
- Выдача и фасеты одного ответа относятся к одному поколению. В RESULTS `returned_count = items.length = min(total, result_limit)`, `limited = (total > result_limit)`. Пагинации поиска нет.
- Score: веса имени=5, проекта/года=4, компании=3, остальных уровней=1. Уникальное слово даёт максимум `вес × коэффициент` по полям (полный токен=2, prefix=1); фраза — `2 × число токенов × максимальный вес поля`. Через границу уровней вес фразы=1. Вклады суммируются после AND; повторения, дубль имени в пути и корневой префикс не добавляют score.
- По умолчанию: с текстом RELEVANCE DESC, без текста PATH ASC. Первое ручное направление: имя ASC, дата/размер DESC. Равенство: natural path ASC → raw path ASC → ID ASC. Natural order сравнивает числа как числа, затем русскую регистронезависимую строку.
- Каждая отправка получает новый `request_state_id`; UI принимает последний ответ своего scope. При 503 прежняя выдача устарела. `marker_id` стабилен для root/parents/raw/kind в одной версии схемы, без переиспользования. Исчезнувший маркер — INVALID_MARKER_SELECTION; новая схема — SCHEMA_VERSION_CHANGED. UI перечитывает значения, сохраняя текст.
- Индекс включает обычные файлы любых расширений/размеров, исключая служебные incoming/manual_review/quarantine и технические файлы. Корень публикуется после полного обхода и сверки. Обновление сохраняет чтение прошлого завершённого поколения; старые пути удалённых/перемещённых файлов исчезают из поиска.

## Правила и публикация

- Имя справочника уникально в компании после trim+casefold. Общий черновик сохраняется целиком с ожидаемой ревизией; конфликт не перезаписывает чужие изменения. Публикации неизменяемы.
- RuleSet объединяет активные версии компании. Побеждает минимальный числовой приоритет совпадения. Разные итоговые цели — конфликт; одинаковые — атрибуция по dictionary_id, затем rule_id.
- Маска проверяет весь BASENAME либо RELATIVE_PATH от входящего источника, включая имя. `*` — любое число символов, `?` — один; для подстроки нужны звёздочки с обеих сторон. В RELATIVE_PATH слеши приводятся к `\`, wildcard пересекает разделители. Нет `**`, escape, regex и OR. Case-folding версионируется, без NFC/NFKC.
- Итоговое имя — буквальная `target_stem` + последний исходный суффикс с прежним регистром. `archive.tar.gz` → `.gz`; `.env`, `README`, `name.` → пустой суффикс. `Invoice.v2` + `.PDF` → `Invoice.v2.PDF`: точки в основе не обрезаются. Имя проверяется по filesystem profile; целевые каталоги уже существуют.
- Simulation заменяет проверяемый справочник и охватывает весь READY-набор компании. Четыре основных PlanCounts дают total, счётчики причин дополнительные. Пустой набор — EMPTY_READY_SET.
- Изменение черновика, RuleSet, READY-набора или истечение TTL инвалидирует тест. Конфликт блокирует публикацию; NO_SCENARIO требует подтверждения simulation_id. Комментарий: 1–500 символов. Занятость целей сама по себе публикацию не блокирует.
- Откат: restore-draft → новый тест → новая публикация с restored_from_version_id. Ручная правка очищает происхождение. Отключение правил — пустая публикация; файлы не возвращаются.

## Очередь и выполнение

- DISCOVERED → WAITING_READY → READY после двух одинаковых наблюдений размера/mtime без признака незавершённой поставки. Изменение/rename требует новой проверки; исчезновение даёт MISSING, видимый только по явному фильтру. SORTED/MANUAL_REVIEW/QUARANTINED доступны в истории/своих списках.
- `counters`/`status_counts` относятся ко всей компании, `matching_count`/`eligible_count` — к фильтрам; attention = REQUIRES_DECISION + RECOVERY_REQUIRED. Выбираются стабильные READY/REQUIRES_DECISION без claim, с повторной серверной проверкой.
- EXPLICIT фиксирует IDs/revisions; ALL_MATCHING — доступные файлы по фильтрам со всех страниц. Несовпадение ожидаемого eligible_count отклоняет снимок. Новые поступления его не меняют. Selection/preview принадлежат user_id; очередь и партии общие.
- Preview фиксирует источники, RuleSet, цели и занятость без перемещения; живёт не дольше selection. DIRECT строит свежий план. Только явный запуск создаёт batch.
- Истёкший selection, изменённые источники и stale preview отклоняются до принятия. Чужой claim даёт SKIPPED/ALREADY_PROCESSING для занятого файла; остальные продолжаются. Claim не меняет содержательную ревизию. Принятый batch фиксирует автора, версии и план; переживает logout/закрытие вкладки и новые публикации.

| Условие | Результат |
|---|---|
| Свободная разрешённая цель | SORTED: атомарное перемещение без перезаписи |
| Нет правила / конфликт правил | MANUAL_REVIEW: плоский ручной разбор компании, исходное имя целиком |
| Цель занята / одинакова у выбранных файлов | Все участники остаются во входящих: REQUIRES_DECISION / TARGET_OCCUPIED |
| Имя занято в ручном разборе | Исходник остаётся: REQUIRES_DECISION / MANUAL_REVIEW_NAME_OCCUPIED |
| Чужой claim | Нет перемещения: SKIPPED / ALREADY_PROCESSING |
| Источник изменился/исчез после принятия | SKIPPED / SOURCE_CHANGED или SOURCE_MISSING; изменение возвращает WAITING_READY |
| Технический сбой, карантин доступен | Подтверждённое перемещение: QUARANTINED / TECHNICAL_ERROR |
| Размещение неизвестно / безопасный карантин невозможен | RECOVERY_REQUIRED, без слепого retry |

- Перед записью проверяются источник, типы, ссылки, границы корня и свободная цель. Операционные корни демо — одна файловая система; copy/delete fallback нет. Ошибка файла не отменяет остальные безопасные операции.
- Intent/phase сохраняются до файлового действия; после сбоя сначала устанавливается исход. `actual_location=null` — размещение не установлено. Первые пять OutcomeCounts дают completed_count; recovery_required незавершён. Завершённый batch: completed_count=selected_count; recovery-batch: finished_at=null.
- Возврат из карантина проверяет ревизию, файл и свободный исходный путь, требует комментарий. Успех — WAITING_READY без автосортировки. Неоднозначность регистрирует operation_id и запрещает повторное перемещение.

## Повторы, страницы и аудит

- Publish, batch и возврат требуют UUID Idempotency-Key, связанный с user_id/операцией/хешем тела. Повтор возвращает прежний результат до проверки TTL; другое тело — IDEMPOTENCY_KEY_REUSED. Принятый ключ хранится с операцией. Новый ключ означает новое явное действие.
- Прочие мутации после потери ответа автоматически не повторяются: перечитать объект/ревизию или список по уникальному имени. Потерянные IDs simulation/selection/preview заменяются новым явным расчётом. После неизвестного logout проверить session.
- Курсор связан с фильтрами/снимком; limit 1–100, default 100. Первая страница: query cursor отсутствует либо JSON cursor=null. Counts относятся ко всему снимку. При первом audit/updates after_event_id отсутствует.
- SYSTEM — вход/выход/блокировка; остальные действия BUSINESS. События содержат автора и связи с операцией по применимости. Поиск/просмотр/копирование не создают бизнес-событий. На batch — одно принятие; на попытку — начало и исход либо RECOVERY_REQUIRED. Уникальность attempt/phase исключает дубли; разрешение неопределённости добавляет событие, не исправляя прошлое. Возврат связан return_operation_id и source_attempt_id.
- Журнал по умолчанию за текущий день в display_timezone, интервал `[from,to)` в UTC. Порядок occurred_at DESC, event_id DESC. Новые события не сдвигают страницы. Индикатор может относиться к событию вне фильтра; обновление повторяет текущие условия. Авторы включают заблокированных с доступными событиями.

## Профиль демо и открытые решения

- UI получает значения из app-config: N=100 (тестовый профиль 10), batch≤1000, текст≤512, TTL снимков/preview/тестов≤300 с, polling batch 1 с и журнала 30 с. Поступления проверяются каждые 5 с; обновления индекса видны ≤5 мин.
- Сессия: absolute 8 ч, idle 30 мин. Успешные аутентифицированные запросы, включая polling, обновляют только idle. expires_at — ближайший срок на момент ответа; 401 окончателен. Часовой пояс — Europe/Moscow.
- Только синтетические данные. Вне API: регистрация/reset, content/OCR/ИИ-поиск, upload/download/edit, глобальный поиск, экспорт, расписание сортировки, создание целей, перезапись/удаление, отмена batch и файловый undo. Ручной разбор обслуживается вне приложения.
- Открыт порядок операторского разрешения RECOVERY_REQUIRED: проверка размещения, запись результата, снятие claim. Публичного endpoint нет; без доказанного исхода состояние сохраняется. Возврат из карантина эту процедуру не заменяет.
- Индекс, ОС/filesystem profile, настройка корней и административные команды выбираются при реализации. Статические проверки не доказывают файловую безопасность, производительность и работу приложения.
