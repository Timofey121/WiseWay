# Wise Way

Wise Way — сервис иерархического поиска по метаданным и ручной сортировки входящих файлов.

Backend синтетической демоверсии: Python 3.11+, FastAPI, SQLite и отдельный файловый worker. Реализованы сессии, поиск с фасетами, версии справочников, simulation, очередь, preview, партии, карантин и журнал. Интерфейс разрабатывается отдельно.

- [OpenAPI 3.1.1](contracts/openapi/wiseway-v1.yaml) — 33 операции: сессии, поиск, справочники, очередь, партии, карантин и журнал. Единственный источник DTO для frontend/backend; примеры встроены.
- [Семантика и границы API](contracts/semantics.md) — правила, которые не выражаются одними типами полей.

Префикс API — `/api/v1`, cookie — `wiseway_session`. Для подключения используйте генератор с поддержкой OpenAPI 3.1. Изменения контракта рассматривают frontend, backend и QA; отдельные копии DTO вручную не поддерживаются.

## Запуск

Нужны Python 3.11+ и `uv`. Команды выполняются из корня репозитория; зависимости зафиксированы в `uv.lock`.

```sh
uv sync --frozen
uv run wiseway init-demo
uv run wiseway serve
```

В другом терминале из того же каталога:

```sh
uv run wiseway worker
```

API: `http://127.0.0.1:8000/api/v1`, проверка: `GET /health`. `init-demo` запрашивает пароль от 12 символов для локальных аккаунтов `worker-atlas`, `worker-nova`, `admin`. Повторная инициализация сохраняет существующие данные и пароли. Миграции применяются автоматически.

Данные находятся в `.wiseway/state`, синтетические файлы — в `.wiseway/sandbox`. Worker проверяет поступления каждые 5 секунд; файл становится READY после двух одинаковых наблюдений. Партии запускаются явно через API. Перезапуск процессов продолжает принятые задания.

Настройки: `WISEWAY_DATA_DIR`, `WISEWAY_SANDBOX_DIR`, `WISEWAY_ORIGINS` (точные origins через запятую), `WISEWAY_SECURE_COOKIE`. По умолчанию разрешены localhost:8000, 127.0.0.1:8000 и localhost:5173. HTTP предназначен для локальной демоверсии; для HTTPS включается Secure cookie.

## Проверка и обслуживание

```sh
uv run pytest -q
uv run ruff check backend
uv run ruff format --check backend
uv run python backend/benchmarks/search.py
uv run python backend/benchmarks/stress.py
```

Тесты используют временные песочницы и проверяют реальные SQLite/файловые операции, контракт, конкурирующие партии, сбои и перезапуск API/worker. Процессному тесту нужен доступ к loopback-порту. Benchmark выводит параметры корпуса и p95; это локальное измерение, не оценка промышленного архива.

Результаты ревью, исправления и незакрытые ограничения: [протокол проверки](backend/VALIDATION.md). Стресс-скрипт возвращает ненулевой код при нарушении SLA; текущий p95 типового поиска при 50 клиентах — 2,44 с при цели 2 с.

`uv run wiseway status` показывает прогресс индекса и незавершённое восстановление. `uv run wiseway recover ATTEMPT_ID` сверяет размещение файла: подтверждённый исход завершает попытку; повтор перемещения возможен только при неизменном источнике и свободной прежней цели. Неоднозначность сохраняет RECOVERY_REQUIRED. `uv run wiseway tick` выполняет один проход worker; `uv run wiseway block-user LOGIN --actor admin` блокирует локальный аккаунт.

Файловые операции требуют одной файловой системы, принадлежащей демосервису песочницы и атомарного rename без перезаписи. Реализованы адаптеры macOS/Linux; фактический прогон выполнен на macOS. Windows, Docker и совместная приёмка с frontend пока не проверены. Гонки с посторонним процессом, меняющим sandbox, переводятся в RECOVERY_REQUIRED; исключительное владение каталогами обязательно. Копирования с последующим удалением и перезаписи файлов нет.

Разработка backend ведётся в `backend-mvp`; после проверки ветка целиком объединяется с `main`.
