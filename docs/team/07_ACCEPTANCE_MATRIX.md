# Матрица приёмки синтетического демо

Статус: базовый перечень ожидаемых проверок, не результаты испытаний. Все 45 сценариев изначально имеют `NOT_RUN`. Точные операции, поля, ограничения и коды ошибок берутся из согласованной версии `02_API_CONTRACT.md`; эта матрица не создаёт второй API.

В первом столбце указаны точные ID требований `01_PROJECT_TZ.md`: `AUTH` — сессия; `SRCH` — поиск и навигация; `DICT` — правила и версии; `QUEUE` — очередь, preview и batch; `FILE` — безопасность файловых операций; `AUD` — аудит; `NFR` — нефункциональные ограничения. Запись `DICT-01…07` включает каждый ID диапазона. Изменение смысла сценария согласует пользователь/QA; изменение API оформляет frontend после обзора backend.

## Правила заполнения

Уровни: `S` — схема/статическая проверка; `M` — mock/UI; `A` — настоящий API и серверная/файловая проверка; `E` — сквозной UI → настоящий API. Указанные в строке уровни — требуемые, а не уже пройденные. Для `A` тестовый backend использует только одноразовую синтетическую песочницу. `M` не доказывает файловую безопасность; `S` не доказывает работу сервера.

Для каждого фактического прогона фиксируются: ID сценария, уровень, дата, версии контракта и сборок, seed корпуса, generation ID, версия словаря, предусловия, шаги, фактический результат, доказательства, статус `NOT_RUN/PASS/FAIL/BLOCKED` и связанный дефект. Параметризованные случаи внутри строки должны быть пройдены все; частичный результат не даёт PASS всей строке. Отсутствующую возможность воспроизведения указывают явно, а не заменяют удобным успешным примером.

Примеры ниже полностью синтетические. `ROOT-A`, `ROOT-B`, `FILE-A`, `FILE-B`, `ACTOR-A`, `ACTOR-B` — роли объектов корпуса, а не обещание конкретного формата ID. Число `L` — лимит выдачи из зафиксированного контракта; срок preview и правила поколений также берутся из него. Для фактического корпуса задаются конкретные значения и независимые эталоны, как описано в `05_QA.md`.

Доказательства: ответы API с безопасными заголовками и correlation ID; снимки UI; записи аудита; независимый инвентарь/контрольные суммы синтетической песочницы; фактический отчёт тестов. Не экспортировать токены, физические пути, реальные имена и трассировки с секретами. Во всех строках исходный статус — `NOT_RUN`.

## Протокол одного прогона

```text
Прогон:
Кандидатная сборка frontend / backend:
Версия API-контракта:
Режим и уровни: S / M / A / E
Среда; версии; seed; generation ID; версия словаря:
Фактические команды подготовки/запуска/проверки:

Q-ID | Уровень | Статус | Фактический результат | Доказательство | Дефект

Итого отдельно по уровням: PASS / FAIL / BLOCKED / NOT_RUN
Непроверенные риски:
Открытые дефекты и владельцы:
Решение пользователя/QA и дата:
```

Нельзя суммировать четыре уровня в одно число «всё прошло»: mock и настоящий backend доказывают разное. Изменение контракта, правил, фикстур или поведения требует определения затронутых строк и повторной проверки; прошлый протокол остаётся привязанным к своей версии.
